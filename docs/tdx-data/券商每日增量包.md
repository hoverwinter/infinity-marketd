# 券商每日增量包验证

来源页面：`https://www.tdx.com.cn/article/daydata.html`

验证日期：`2026-09-04`。本页记录一次可复核的格式和数据一致性检查，不代表通达信对该二进制格式作出了稳定性承诺。

## 验收目标

当前 `infinity_market.a_share_bars_1d` 所需的最小数据为：

- 沪、深、北市场和证券代码；
- 交易日期；
- 未复权开盘、最高、最低、收盘价；
- 成交量和成交额。

验收分成两个口径：

1. 沪深北 A 股股票日 K 增量；
2. 完整替代 `hsjday.zip` 中的股票、指数、基金、债券等全部证券。

`g3day` 没有北京市场文件。两个包的 `.cod` 都是 150-byte 定长记录；`g3day` 的 `.mdt` 是 256-byte 定长记录，`g4day` 的 `.md1` 是 512-byte 定长记录。同一市场内，代码记录和数据记录按下标一一对应，`.cod` 每条记录前 6 bytes 是证券代码。

## g4day 已验证字段

下表是对 `.md1` 的实测解码，不是官方公开结构定义：

| Offset | Size | Observed type | Field |
| --- | ---: | --- | --- |
| 0 | 4 | `uint32` | 记录序号 |
| 4 | 8 | `float64` | 前收盘价 |
| 12 | 8 | `float64` | 开盘价 |
| 20 | 8 | `float64` | 最高价 |
| 28 | 8 | `float64` | 最低价 |
| 36 | 8 | `float64` | 收盘价 |
| 56 | 8 | `uint64` | 成交量 |
| 72 | 8 | `float64` | 成交额 |

抽样 `sh:600519`、`sz:000001`、`bj:920982` 后，开高低收和成交量均与同日完整 `.day` 包一致。`sh:600519` 的 `g4day` 数据为前收 `1298.88`、开 `1295.88`、高 `1338.86`、低 `1295.60`、收 `1330.00`、成交量 `4,541,564`。

## 全量对比结果

以 `2026-09-04` 已导入的完整 `.day` 数据为基准：

| Check | Result |
| --- | ---: |
| 基准库当日全部证券行数 | 9,657 |
| g4day 缺失基准证券 | 0 |
| A 股股票行数 | 5,547 |
| A 股股票缺失 | 0 |
| A 股股票 OHLC 不匹配 | 0 |
| A 股股票成交量不匹配 | 0 |
| A 股股票成交额相对误差超过 1 ppm | 0 |
| A 股股票价格最大绝对差 | 0.004 |
| A 股股票成交额最大相对差 | `5.95902385e-08` |

A 股股票筛选口径为：上海 `6xxxxx`，深圳 `000xxx`、`001xxx`、`002xxx`、`003xxx`、`300xxx`、`301xxx`，北京当前股票代码 `920xxx`。北京 `899050`（北证50）和 `899601`（北证专精特新）是指数，不能按宽泛的 `8/9xxxxx` 规则当成股票；它们在本次包中都有有效行情，也是宽口径统计比严格股票口径多 2 行的原因。价格微小差异来自 `g4day` 的 `float64` 与 `.day` 整数分精度；成交额差异来自 `.day` 的 `float32` 精度。

若比较全部 9,657 个证券，存在 2,414 个价格差异和 335 个成交量差异，主要集中在可转债等非股票证券。例如 `.day` 当前统一按股票规则缩放，而 `g4day` 显示了不同的品种口径。这暴露的是现有全品种归一化规则不足，不能据此认定 `g4day` 数据错误。

## 结论

| Requirement | g3day | g4day |
| --- | --- | --- |
| 沪深北 A 股日 K 覆盖 | 不符合：无北京市场 | 符合 |
| OHLCV 和成交额可解码 | 不符合：成交量编码尚未确认 | 符合 |
| 可直接交给现有 `.day` parser | 不符合 | 不符合 |
| 可作为 A 股每日增量源 | 不采用 | 已由 `import-tdx-g4-day` 支持 |
| 可完整替代全品种 `hsjday.zip` | 不符合 | 尚未符合，需要品种分类和缩放规则 |

因此，历史基线继续使用 `.day` 完整包，个别证券缺口可以使用 TDX 在线接口补数，每日盘后全市场增量使用 `g4day`。`g4day` 导入器在写入前校验日期、市场文件完整性、`.cod`/`.md1` 记录数一致、代码唯一性和 A 股品种范围；不能把 `.md1` 文件改后缀后交给 `.day` parser。

## 导入命令

从官方地址下载指定日期并完成全量校验：

```bash
go run ./cmd/marketd import-tdx-g4-day \
  --date 2026-09-04 \
  --dry-run
```

确认 dry-run 的日期、SHA-256、三市场记录数和写入行数后，去掉 `--dry-run` 写入 `a_share_bars_1d`：

```bash
go run ./cmd/marketd import-tdx-g4-day \
  --date 2026-09-04 \
  --config configs/config.yaml
```

重放已经下载的本地包：

```bash
go run ./cmd/marketd import-tdx-g4-day \
  --file /path/to/20260904.zip \
  --date 2026-09-04 \
  --dry-run
```

本地模式的 `--date` 可省略，此时从 ZIP 内六个文件名推导；如果提供，则作为日期一致性断言。远程模式必须显式指定 `--date`，下载地址为 `https://www.tdx.com.cn/products/data/data/g4day/YYYYMMDD.zip`。

## 写入边界

- 只导入上海 `6xxxxx`、深圳 `000/001/002/003/300/301xxx`、北京当前 `920xxx` 股票的有效成交记录；`899050`、`899601` 等北京指数不会写入股票日线。
- 非 A 股记录和当天无成交记录只计入 `rows_skipped`，不会生成零值日K。
- 缺少任一市场文件、日期不一致、定长记录错位、代码重复或有效股票行情异常时整包失败，不会部分写入。
- 压缩包上限为 16 MiB，单个解压条目上限为 64 MiB，全部匹配条目合计上限为 128 MiB，每市场最多 100,000 条记录。
- 正式导入只写未复权 `a_share_bars_1d` 及对应任务、水位元数据；不会刷新 XDXR、复权因子或派生指标。
- 命令不会由实时行情查询触发，也不会创建定时任务。盘中最后一根临时日K仍由实时行情展示路径负责，不写入正式日线表。
