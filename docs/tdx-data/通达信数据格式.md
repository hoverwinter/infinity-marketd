# 通达信数据格式

本文档整理 `infinity-marketd` 首期需要支持的通达信数据格式，重点面向 Go parser 和 ClickHouse 写入实现。

范围：

- 本地 TDX 日线 `.day`
- 本地 TDX 1 分钟 / 5 分钟文件 `.lc1` / `.lc5`
- 本地 TDX 兼容分钟文件 `.1` / `.5`
- 远程 TDX 标准行情接口返回数据的结构要点
- 官方页面下载的数据包归档说明见本目录中的页面级文档：
  - `个人行情数据.md`
  - `券商所有数据.md`
  - `专业财务数据.md`

非目标：

- 不覆盖所有通达信扩展市场格式。
- 不覆盖财务包 `tdxfin.zip`、股票资料包 `tdxgp.zip` 的完整字段。
- 不假设 TDX 远程行情服务器提供主动推送；公开可复刻接口按请求/响应处理。

## 数据源分类

`marketd` 处理 TDX 数据时必须先区分来源。三类来源不能混成一个“TDX 数据源”：

| Source class | Meaning | Examples | Current role |
| --- | --- | --- | --- |
| `client-local` | 已安装 TDX 客户端在本机维护的目录和文件 | `C:/new_tdx/vipdoc/...`, `T0002/blocknew/`, 本机 `gbbq`, 本机扩展行情目录如 `Lxxx` | 适合读取客户端已有状态；完整性取决于客户端版本、更新记录和用户本地配置 |
| `offline-package` | 从 TDX 官网/页面下载的离线 ZIP 或 `.dat` 包 | `hsjday.zip`, `shlday.zip`, `tdxfin.zip`, `tdxgp.zip` | 适合全量 bootstrap/backfill；应校验清单、大小、日期和格式版本 |
| `online-provider` | 连接 TDX `hq` / `exhq` 行情服务器按请求读取 | `hq-xdxr`, `hq-block`, `exquote-bars`, `/api/tdx/*` | 默认只读 JSON/provider data；不隐式写 ClickHouse |

设计规则：

1. `client-local` reader 只读本机文件和 ClickHouse，不连接 TDX server。
2. `offline-package` importer 从显式 ZIP/包文件导入，适合作为可重复历史回填来源。
3. `online-provider` 能力用于实时/临时查询和交叉验证；要落库必须先单独设计 schema、逻辑键、去重、保留周期和查询 contract。
4. 同名或相近数据不能直接等价。例如在线 `hq-xdxr` 不能代表本机 `gbbq` 已读完；在线 `hq-block` 不能代表 `T0002/blocknew` 自定义板块已支持。

## 本地已保存数据包

本仓库当前已将已下载的官方数据包保存到 `data/`：

| File | Source page | Purpose |
| --- | --- | --- |
| `data/hsjday.zip` | `vipdata.html` | 个人版沪深京日线数据完整包 |
| `data/shzsday.zip` | `alldata.html` | 上证指数日线样本包 |
| `data/38day.zip` | `alldata.html` | 宏观指标日线样本包 |
| `data/tdxfin.zip` | `stockfin.html` | 专业财务数据包 |
| `data/tdxgp.zip` | `stockfin.html` | 股票交易/扩展指标数据包 |

`data/` 下保存的是原始 ZIP，不在源代码目录中解压。解析实现应从 fixture 或明确指定的数据目录读取，避免把大体积生成文件混入 `internal/` 或测试源码。

## 目录结构

典型 TDX `client-local` 目录中的 A 股行情部分：

```text
<tdx-root>/
  vipdoc/
    sh/
      lday/
        sh600519.day
      minline/
        sh600519.lc1
      fzline/
        sh600519.lc5
    sz/
      lday/
        sz000001.day
      minline/
        sz000001.lc1
      fzline/
        sz000001.lc5
    bj/
      lday/
        bj920002.day
      minline/
        bj920002.lc1
```

这段只描述标准 A 股/指数本地 K 线路径。它不代表所有 `client-local` 数据都在 `vipdoc/sh|sz|bj` 下。

常见非 A 股 K 线的 `client-local` 数据还包括：

```text
<tdx-root>/
  T0002/
    blocknew/
      blocknew.cfg
      *.blk
      # 用户自定义板块/自选股

    hq_cache/
      # 部分系统板块/缓存配置，具体随客户端版本变化

  gbbq
    # 股本变迁/权息文件，实际位置需要用客户端样本确认

  <extension-market-dir>/
    # 扩展行情本地目录，用户样本中可能是 Lxxx
    # 文件名可出现 29#A1801.day 这类 ex_daily 形态
```

部分通达信版本或导出文件可能不带 `vipdoc/` 前缀，分钟文件后缀也可能为 `.1` / `.5`。

marketd 首期建议支持：

```text
vipdoc/<market>/lday/<market><code>.day
vipdoc/<market>/minline/<market><code>.lc1
vipdoc/<market>/fzline/<market><code>.lc5
vipdoc/<market>/minline/<market><code>.1
vipdoc/<market>/fzline/<market><code>.5
```

新增 client-local reader 命令：

```bash
marketd import-tdx-gbbq --file C:/new_tdx/gbbq --dry-run
marketd import-tdx-block --file C:/new_tdx/block_gn.dat --scope system --dry-run
marketd import-tdx-block --file C:/new_tdx/T0002/blocknew --scope custom --dry-run
marketd import-tdx-ex-daily --file C:/new_tdx/L001/29#A1801.day --market 29 --code A1801 --dry-run
marketd write-tdx-custom-block --file C:/new_tdx/T0002/blocknew --block-id watch --add sh:600519 --dry-run
```

这些命令属于 `client-local`，不读取下载 ZIP，也不连接 TDX server。

## Client-Local 参考数据格式

### `gbbq`

`gbbq` 是股本变迁/权息事件文件。当前 parser 读取：

```text
uint32 count
count * 29-byte records
```

每条记录规范化为：

```text
market
symbol
event_date
category
event_seq
event_name
cash_dividend / allotment_price / bonus_shares / allotment_shares
pre_float_shares / post_float_shares / pre_total_shares / post_total_shares
```

这些记录写入 `infinity_market.a_share_capital_change_events`。同日同类别多条事件用 `event_seq` 区分。真实 TDX 客户端 `gbbq` 文件可能存在版本差异，必须用 client-local fixture 做回归测试。

### 系统板块文件

系统板块文件如 `block.dat`、`block_zs.dat`、`block_fg.dat`、`block_gn.dat` 使用固定头和固定成员区：

```text
384-byte header
uint16 block_count
for each block:
  9-byte GBK/GB18030 block name
  uint16 stock_count
  uint16 block_type
  2800-byte fixed member area
```

每个成员代码按 TDX block code 解析出 `market` 和 `symbol`。导入时生成 deterministic `snapshot_id`，写入：

```text
tdx_block_snapshots
tdx_block_definitions
tdx_block_memberships
```

### 自定义板块

自定义板块按 `T0002/blocknew` 目录处理：

```text
blocknew.cfg
<block-id>.blk
```

`blocknew.cfg` 使用 120-byte 记录：

```text
50-byte GBK/GB18030 block name
70-byte block file id
```

对应 `<block-id>.blk` 是成员代码列表。写入命令必须先备份、写临时文件、原子替换、再重新读取校验。

### `ex_daily`

`ex_daily` 是扩展行情本地日线，不使用 A 股 `vipdoc/sh|sz|bj` 市场语义。文件名可出现 `29#A1801.day` 这类形态，用户客户端中也可能位于 `Lxxx` 目录。

当前 parser 读取 32-byte little-endian 记录：

```text
uint32 date
float32 open
float32 high
float32 low
float32 close
uint32 amount_or_amount_bits
uint32 volume_or_position
float32 settlement_price
```

第一版命令要求显式提供：

```text
--file
--market
--code
```

不对 `Lxxx` 或 `vipdoc/ds/lday` 做自动 discovery，直到真实 fixture 覆盖具体目录规则。

## 市场和代码识别

文件位置优先：

```text
.../sh/... -> sh
.../sz/... -> sz
.../bj/... -> bj
```

文件名通常为：

```text
sh600519.day
sz000001.lc1
bj920002.day
```

解析规则：

```text
market = 文件名前两位或路径 market 目录
symbol = 文件名去掉 market 前缀和后缀后的 6 位代码
```

无路径上下文时的 fallback：

```text
920* / 8* / 4* -> bj
6* / 9*        -> sh
其他常见 A 股  -> sz
```

注意：`920002` 应归为 `bj`，不得因为 `9` 开头误归为 `sh`。

## 字节序

本地行情文件使用 little-endian。

Go 实现中应使用：

```go
binary.LittleEndian
```

所有本地 K 线记录目前按固定 32 bytes 一条处理。

如果文件长度不是 32 的整数倍：

```text
完整记录正常解析
尾部不足 32 bytes 记录 quality issue
```

## 本地日线 `.day`

### 记录长度

```text
32 bytes / record
```

### Go struct 草案

```go
type TdxDayRecord struct {
    Date     uint32  // YYYYMMDD, e.g. 20260605
    Open     uint32  // price in cents
    High     uint32  // price in cents
    Low      uint32  // price in cents
    Close    uint32  // price in cents
    Amount   float32 // transaction amount
    Volume   uint32  // volume
    Reserved uint32
}
```

等价 unpack 格式：

```text
<IIIIIfII
```

字段偏移：

| Offset | Size | Type | Field | Unit |
| --- | ---: | --- | --- | --- |
| 0 | 4 | uint32 | date | `YYYYMMDD` |
| 4 | 4 | uint32 | open | cents |
| 8 | 4 | uint32 | high | cents |
| 12 | 4 | uint32 | low | cents |
| 16 | 4 | uint32 | close | cents |
| 20 | 4 | float32 | amount | raw amount |
| 24 | 4 | uint32 | volume | raw volume |
| 28 | 4 | uint32 | reserved | ignored |

### 归一化

写入 `infinity_market.a_share_bars_1d`：

```text
market      = path/filename market
symbol      = filename code
trade_date  = Date parsed as YYYY-MM-DD
open        = Open / 100.0
high        = High / 100.0
low         = Low / 100.0
close       = Close / 100.0
amount      = Amount
volume      = Volume
```

输入文件、mtime、解析格式记录到 `infinity_ops.task_runs`，仅用于运行诊断；这些字段不进入行情事实表，也不作为数据源维度。

### 校验

必须校验：

```text
date 是合法日历日期
open/high/low/close >= 0
high >= low
文件尾部无不完整记录，若有则记录 quality issue
```

建议校验：

```text
非停牌记录 close > 0
volume/amount 异常小浮点值归零或记录诊断
同一 symbol + trade_date 重复记录记录 quality issue
```

## 本地分钟 `.lc1` / `.lc5`

`.lc1` 和 `.lc5` 是通达信本地分钟 K 线文件。常见布局为 OHLC 使用 `float32`。

### 记录长度

```text
32 bytes / record
```

### 日期编码

分钟文件日期不是 `YYYYMMDD`，而是 16-bit packed date：

```text
year  = date_num / 2048 + 2004
month = (date_num % 2048) / 100
day   = (date_num % 2048) % 100
```

### 时间编码

时间是从 00:00 开始的分钟数：

```text
hour   = minute_num / 60
minute = minute_num % 60
```

例如：

```text
09:31 -> 571
15:00 -> 900
```

### Go struct 草案

```go
type TdxLCMinuteRecord struct {
    Date     uint16  // packed date
    Time     uint16  // minutes from 00:00
    Open     float32
    High     float32
    Low      float32
    Close    float32
    Amount   float32
    Volume   uint32
    Reserved uint32
}
```

等价 unpack 格式：

```text
<HHfffffII
```

字段偏移：

| Offset | Size | Type | Field | Unit |
| --- | ---: | --- | --- | --- |
| 0 | 2 | uint16 | date | packed date |
| 2 | 2 | uint16 | time | minutes from 00:00 |
| 4 | 4 | float32 | open | price |
| 8 | 4 | float32 | high | price |
| 12 | 4 | float32 | low | price |
| 16 | 4 | float32 | close | price |
| 20 | 4 | float32 | amount | raw amount |
| 24 | 4 | uint32 | volume | raw volume |
| 28 | 4 | uint32 | reserved | ignored |

### 归一化

写入对应周期的行情表：

```text
market      = path/filename market
symbol      = filename code
bar_time    = decoded timestamp in Asia/Shanghai
trade_date  = date(bar_time)
open        = Open
high        = High
low         = Low
close       = Close
amount      = Amount
volume      = Volume
```

`.lc1` / `.1` 写入 `infinity_market.a_share_bars_1m`。

`.lc5` / `.5` 写入 `infinity_market.a_share_bars_5m`。

输入文件、mtime、解析格式记录到 `infinity_ops.task_runs`，仅用于运行诊断；这些字段不进入行情事实表，也不作为数据源维度。`.lc1/.lc5` 的 `input_format` 记录为 `tdx.lcmin.<HHfffffII>`；`.1/.5` 的 `input_format` 记录为 `tdx.intmin.<HHIIIIfII>`。

32 bytes / record
```

```

| Offset | Size | Type | Field | Unit |
| --- | ---: | --- | --- | --- |
| 0 | 2 | uint16 | date | packed date |
| 2 | 2 | uint16 | time | minutes from 00:00 |
| 4 | 4 | uint32 | open | cents |
| 8 | 4 | uint32 | high | cents |
| 12 | 4 | uint32 | low | cents |
| 16 | 4 | uint32 | close | cents |
| 20 | 4 | float32 | amount | raw amount |

### 归一化

```text
open  = Open / 100.0

```

其他字段同 `.lc1`。

## 分时线和 1 分钟 K 的区别

TDX 中需要区分：

```text
1-minute K:
  OHLCV bar
  一分钟一个 bar
  适合写 infinity_market.a_share_bars_1m

分时线:
  price + volume point
  通常 240 个点
  不是 OHLCV
  适合写 infinity_market.a_share_intraday_points
```

不要把 `get_minute_time_data` 的返回直接当作 1 分钟 K。

## 远程 TDX 标准行情接口要点

公开可复刻的 TDX 标准行情接口是 TCP 请求/响应模型。实现 Go 远程客户端时，需要复刻：

```text
TCP connect
setup handshake
send request packet
read 16-byte response header
read response body
zlib decompress when zip_size != unzip_size
decode body
```

响应头长度：

```text
16 bytes
```

响应头解包逻辑：

```text
<IIIHH
```

其中关键字段：

```text
zip_size
unzip_size
```

当 `zip_size != unzip_size` 时，body 需要 zlib 解压。

### 远程 1 分钟 K

远程 K 线接口可返回 1 分钟 OHLCV。

TDX K 线 category 常见值：

```text
0  = 5m
1  = 15m
2  = 30m
3  = 1h
4  = day
5  = week
6  = month
7  = 1m
8  = 1m
9  = day
10 = quarter
11 = year
```

实践中 `category=8` 可用于 1 分钟 K。

单次返回数量通常最多 800 条。`count` 是单次请求页大小，`start` 是从最近 bar 向历史方向偏移的位置。

分页读取应使用：

```text
start=0, count=800      # 最近 800 根
start=800, count=800    # 再往前 800 根
start=1600, count=800   # 更早 800 根
...
```

不要把 800 理解成服务器只保留最近 800 天。2026-06-07 实测标准行情服务器 `180.153.18.170:7709`：

```text
sh:600519 category=9 start=0    -> 2023-02-16 .. 2026-06-05
sh:600519 category=9 start=5600 -> 2001-08-27 .. 2003-01-21
sz:000001 category=9 start=8000 -> 1991-04-03 .. 1992-10-06
```

远程 K 线导入如果需要全量或长区间历史，应按 `start` 分页、按目标时间区间截断，并用 ClickHouse 逻辑键处理重复写入。

远程 K 线返回字段逻辑：

```text
datetime
open
high
low
close
volume
amount
```

远程 K 线价格和成交量使用压缩差分编码，不能按本地文件 fixed struct 直接解码。需要实现 TDX 的可变长有符号 price diff 和 volume 解码。

`marketd` 已实现在线 K 线只读命令：

```text
hq-bars
hq-index-bars
```

这些命令只返回 JSON，不写入 ClickHouse。后续如果要把远程 K 线作为补数来源写入 `a_share_bars_*`，需要另行设计导入、水位、质量诊断和分页补数语义。

### 今日分时

今日分时接口返回：

```text
price
vol
```

通常最多 240 个点。

远程分时价格使用差分累计：

```text
last_price = last_price + price_raw
price = last_price * coefficient
```

分时点本身不包含完整 OHLC。

### 历史分时

历史某日分时接口返回结构与今日分时类似：

```text
price
vol
```

请求参数包含：

```text
market
code
date as YYYYMMDD
```

历史分时按单日请求，不按 `start/count` 翻页。完整 A 股交易日通常返回 240 个 `price + vol` 点；非交易日、上市前日期或 server 未返回的日期为空。

2026-06-07 实测标准行情服务器：

```text
180.153.18.170:7709 sh:600519 2001-08-27 -> 240 points
60.191.117.167:7709 sh:600519 2001-08-27 -> 240 points
180.153.18.170:7709 sh:600519 2001-08-24 -> 0 points
180.153.18.170:7709 sh:600519 2024-06-08 -> 0 points
```

因此历史分时可覆盖远早于最近 800 天的数据，但实现不能假设任意日期必有数据。

`marketd` 已实现在线分时只读命令：

```text
hq-minute
hq-history-minute
```

这些命令返回 `price + volume` point，不写入 ClickHouse，也不会把分时点转换为 1 分钟 OHLCV。

需要持久化标准行情分时点时，使用显式导入命令：

```text
import-tdx-intraday-points
```

该命令写入 `infinity_market.a_share_intraday_points`。本地 `.lc1` / `.1` 导入仍只写 `a_share_bars_1m`，不会隐式派生分时点。

### 分笔成交

分笔成交接口返回逐笔或聚合成交点：

```text
time
price
volume
buy_or_sell
```

当日接口按 `start/count` 分页：

```text
get_transaction_data
```

历史接口按 `YYYYMMDD + start/count` 请求：

```text
get_history_transaction_data
```

`marketd` 已实现只读命令：

```text
hq-transactions
hq-history-transactions
```

这些命令不写入 ClickHouse。分笔成交不等同于实时快照，也不等同于 K 线。

### F10 / 公司信息、除权除息、财务和板块

标准行情服务器还提供以下在线只读接口：

```text
get_company_info_category
get_company_info_content
get_xdxr_info
get_finance_info
get_block_info_meta
get_block_info
```

`marketd` 对应命令：

```text
hq-company-categories
hq-company-content
hq-xdxr
hq-finance
hq-block-meta
hq-block
```

TDX 文本字段常见 GBK/GB18030 编码，`marketd` 输出 JSON 前会解码为 UTF-8。以上命令均为只读在线查询，不写入 ClickHouse。

### 实时快照

实时快照接口可返回：

```text
price
last_close
open
high
low
volume
current volume
amount
bid/ask 1-5
bid/ask volume 1-5
server time
```

适合写：

```text
infinity_market.a_share_quote_snapshots
```

## 质量诊断建议

解析阶段必须记录但不应直接中断整个导入的情况：

```text
missing file
unsupported suffix
file size not multiple of 32
invalid date
invalid time
high < low
zero valid rows
duplicate logical key
unsupported market
unsupported code format
```

写入阶段必须记录：

```text
clickhouse connection error
batch insert failure
partial write
watermark update failure
```

## ClickHouse 目标表映射

映射原则：

1. TDX 文件格式不同，不等于 ClickHouse 表一定不同；ClickHouse 表按业务查询形态和数据生命周期设计。
2. 日线、1 分钟、5 分钟虽然都是 OHLCV，但必须写入不同物理表，不能用 `bar_interval` 混在同一张表里。
3. 行情事实表不保存 source。输入文件、解析格式和异常诊断只记录到 `infinity_ops`，用于运行诊断，不参与事实建模。
4. 分时线是 `price + volume` point，不是 1 分钟 OHLCV，必须单独写入 `a_share_intraday_points`。

| TDX input | Data shape | Target table |
| --- | --- | --- |
| local `.day` | daily OHLCV | `infinity_market.a_share_bars_1d` |
| local `.lc1` / `.1` | 1m OHLCV | `infinity_market.a_share_bars_1m` |
| local `.lc5` / `.5` | 5m OHLCV | `infinity_market.a_share_bars_5m` |
| remote security bars category 8 | 1m OHLCV | `infinity_market.a_share_bars_1m` |
| remote minute time data | price + volume points | `infinity_market.a_share_intraday_points` |
| remote security quotes | realtime quote snapshot | `infinity_market.a_share_quote_snapshots` |

## 实现顺序建议

1. 实现 `.day` parser。
2. 实现 `.lc1` parser。
3. 加入 `.1` parser fallback。
4. 写入 ClickHouse daily / 1m 表。
5. 加水位和质量诊断。
6. 再实现远程 1m K。
7. 最后实现实时快照和今日分时轮询。

## 参考来源

本说明基于以下已验证实现整理：

- Infinity 当前 Python TDX loader 的 `.day` 解析契约。
- `tdxpy` / `mootdx` 的本地 reader：
  - `TdxDailyBarReader`: `<IIIIIfII`
  - `TdxLCMinBarReader`: `<HHfffffII`
  - `TdxMinBarReader`: `<HHIIIIfII`
- `tdxpy` 标准行情 parser：
  - `get_security_bars`
  - `get_minute_time_data`
  - `get_history_minute_time_data`
  - `get_security_quotes`

这些格式应通过 fixture tests 固化，不能只依赖文档假设。
