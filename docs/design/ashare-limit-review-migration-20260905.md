## 选择与执行

1. 通过只读 HTTP 查询确认新复盘表尚不存在，执行现有 bootstrap 创建缺失表；没有 ALTER、DROP、TRUNCATE、DETACH 或数据替换。
2. 归档两套原始文件并记录 SHA-256。重叠的 112 个日期选近期 THS 快照，其他日期选历史规则回放，共 2,482 份历史快照和 112 份近期快照；不把两个池简单叠加。被排除的 112 份历史文件也保留归档。
3. 清单相邻日期的 prev_trade_date 完整衔接。对全部日期区间按季度检查六个查询接口，258 项检查均为空，再开始写入，避免覆盖既有订正。
4. 显式按 `--snapshot-kind historical-replay --percent-unit ratio` 或 `--snapshot-kind ths --percent-unit percent` 归一，12 个年度/来源批次先全量 dry-run，再串行正式导入。
5. 三个已验证专用指数分别预览、正式导入，运行时核对目录身份并记录较晚的历史起点。

旧 Python 已确认的占位 0 不作为客观零保存：历史换手率/封单/开板次数及扩展统计转 NULL；近期未取得的金额等按 THS 旧写入器语义处理。`generic` profile 不改变这些数值，非零的已有订正保留。历史未知封板率在查询重建时仍为 NULL，不能因为缺少炸板记录就生成 100%。

导入保留 2,587 条快照级质量告警及 3 条指数历史覆盖告警。15 个任务均为 `degraded`，表示保留了已知数据缺口；写入均完成，没有错误跳行，`rows_skipped=0`。
